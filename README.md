# Telegram-бот Yubara «Юбара»

Бот запускается в режиме polling и использует SQLite, Groq и HTTP healthcheck,
который Render проверяет на порту `PORT`.

## Локальный запуск

1. Установите Python 3.11.
2. Создайте виртуальное окружение и установите зависимости:
   `pip install -r requirements.txt`
3. Скопируйте `.env.example` в `.env` и заполните переменные.
4. Запустите `python main.py`.

## Деплой на Render

Создайте **Web Service**, подключите репозиторий и укажите:

- Build Command: `pip install -r requirements.txt`
- Start Command: `python main.py` (команда Procfile: `web: python main.py`)
- Корневой `.python-version` закрепляет Python `3.11.11` для Render.

Если в настройках Environment сервиса задан `PYTHON_VERSION`, он может
переопределять версию из `.python-version`; укажите там `3.11.11` или удалите
это переопределение, затем запустите новый Deploy. Приложение также явно
создаёт asyncio event loop перед запуском polling для совместимости с
средами Python, в которых loop больше не создаётся автоматически.

В Environment добавьте `TELEGRAM_TOKEN`, `GROQ_API_KEY`, `ADMIN_ID`,
`BACKUP_CHANNEL_ID` и `AI_HORDE` (API-ключ AI Horde). Render задаёт `PORT`
для Web Service автоматически; локально бот использует `8080`, если `PORT`
не задан. Если `AI_HORDE` не задан, генерация использует анонимный доступ
AI Horde.

## Доступ и изображения

В `/adm` можно создавать одноразовые ключи обычного доступа и приглашения
администраторов, выбирая срок: навсегда, 30 дней, 7 дней или 24 часа
(срок отсчитывается с активации ключа). Существующие пользователи при
обновлении остаются бессрочными. У администраторов полный доступ к панели;
кнопки в панели позволяют отзывать ключи, пользовательский доступ и права
дополнительных администраторов. Главный `ADMIN_ID` не отзывается.
Администратор может отправить `/break` в личном чате с ботом для штатной
остановки текущего процесса, включая финальную остановку задач и резервное
копирование. Render может автоматически перезапустить остановленный сервис.

Для генерации отправьте `/image описание` или явно попросите нарисовать
изображение. Pollinations доступен глобально не чаще раза в две минуты;
AI Horde показывает позицию и примерное ожидание, имеет кнопку отмены и
автоматически выбирает доступную аниме-модель. Изображения выдаются в чат
и публикуются в настроенном `BACKUP_CHANNEL_ID`. Одновременно выполняется
только одна генерация; остальные запросы ждут своей очереди. Для фоновых запросов
боту нужны права отправки фотографий в этот канал.
В меню перед генерацией есть кнопка настроек: предпочтение аниме-модели,
модель Pollinations (Flux или Turbo), размер, негативный промпт и seed.
Настройки сохраняются отдельно для каждого чата: в группе они общие для всех
участников этой группы.
Если AI Horde удалит долго ожидающее задание (`RequestNotFound`), бот
автоматически поставит его в очередь повторно; общее время ожидания не
ограничено.

## Канал резервных копий

Создайте приватный канал и добавьте бота администратором с правами публикации,
удаления сообщений и закрепления сообщений. Узнать ID можно, добавив бота в
канал и посмотрев `channel_post.chat.id` в ответе Bot API `getUpdates` после
публикации нового поста. Запрос к Bot API выполняйте только со своим токеном
и не публикуйте ссылку с токеном. Также можно переслать пост из канала
боту, показывающему ID. Обычно ID канала выглядит как `-1001234567890`;
укажите это число в `BACKUP_CHANNEL_ID`.

Бот восстанавливает данные из закреплённого документа канала, а если это
невозможно — из локального `database_backup.db`. Резервная копия отправляется
раз в 10 минут только после изменений базы данных. В канал также отправляются
события запуска и остановки бота, а предупреждения и ошибки публикуются без
трассировок и ссылок, содержащих промпты или ключи. Служебные сообщения
Telegram о закреплении бот удаляет автоматически; для этого необходимо право
удаления сообщений.
