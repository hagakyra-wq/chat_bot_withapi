# Telegram-бот Yubara «Юбара»

Бот запускается в режиме polling и использует SQLite, Groq и HTTP healthcheck,
который Render проверяет на порту `PORT`.

## Локальный запуск

1. Установите Python 3.11.
2. Создайте виртуальное окружение и установите зависимости:
   `pip install -r requirements.txt`
3. Скопируйте `.env.example` в `.env` и заполните переменные.
4. Запустите `python main.py`.

## Деплой на Render

Создайте **Web Service**, подключите репозиторий и укажите:

- Build Command: `pip install -r requirements.txt`
- Start Command: `python main.py` (команда Procfile: `web: python main.py`)
- Корневой `.python-version` закрепляет Python `3.11.11` для Render.

Если в настройках Environment сервиса задан `PYTHON_VERSION`, он может
переопределять версию из `.python-version`; укажите там `3.11.11` или удалите
это переопределение, затем запустите новый Deploy. Приложение также явно
создаёт asyncio event loop перед запуском polling для совместимости с
средами Python, в которых loop больше не создаётся автоматически.

В Environment добавьте `TELEGRAM_TOKEN`, `GROQ_API_KEY`, `ADMIN_ID`,
`BACKUP_CHANNEL_ID` и `LOGS_CHAT`. `BACKUP_CHANNEL_ID` используется только
для резервных копий базы данных, а операционные предупреждения и события
отправляются отдельно в `LOGS_CHAT`. Render задаёт `PORT` для Web Service автоматически;
локально бот использует `8080`, если `PORT` не задан.

## Доступ и изображения

В `/adm` можно создавать одноразовые ключи обычного доступа и приглашения
администраторов, выбирая срок: навсегда, 30 дней, 7 дней или 24 часа
(срок отсчитывается с активации ключа). Существующие пользователи при
обновлении остаются бессрочными. У администраторов полный доступ к панели;
кнопки в панели позволяют отзывать ключи, пользовательский доступ и права
дополнительных администраторов. Главный `ADMIN_ID` не отзывается.
Администратор может отправить `/break` в личном чате с ботом для штатной
остановки текущего процесса, включая финальную остановку задач и резервное
копирование. Render может автоматически перезапустить остановленный сервис.

Юбара использует последние 20 сообщений текущего чата как контекст ответа.
В обычном разговоре она отвечает по делу и обычно кратко, но может дать
развёрнутое объяснение, когда этого требует вопрос. По запросу подробно
пересказывает сообщения за последние 12 часов. В разрешённых группах
приветствует новых участников и иногда ставит реакцию на сообщение, на которое
ответила.
На вопрос «что ты знаешь обо мне?» Юбара выдаёт профиль по сохранённым сведениям
текущего чата, не смешивая данные участников из других групп. На запросы вроде
«что ты знаешь о группе?» или «расскажи о нас» она перечисляет известные факты
об участниках; профиль формируется по сохранённым данным, а не только по ответу
языковой модели.
Профиль пользователя и его монеты общие для всех чатов. В профиле показываются
имя, Telegram ID, username, кличка, возраст, пол, ID известных групп и заметки.
В группе можно запросить `/profile` для себя, `/profile -1001234567890` для
профилей участников разрешённой группы или сказать «профиль группы ID».
Существующие групповые заметки переносятся в единый профиль при обновлении.

Вызовите её, например, фразой «Юбара, я вызываю тебя на дуэль», чтобы сыграть
в кости. Бот ждёт завершения анимации каждого броска, прежде чем продолжить.
Новый игрок начинает с 5 монет; победа даёт 2, поражение отнимает 1,
при ничьей баланс не меняется. Счёт хранится глобально по Telegram ID пользователя;
текущий счёт можно узнать словом «баланс».
Команда «Юбара, дэл 3» удаляет три последних сообщения Юбары в текущем чате;
старое «дэл» в ответ на её сообщение по-прежнему удаляет только это сообщение.
Можно также попросить «Юбара, удали последние 3 сообщения» или «удали последнее
сообщение» в личном чате. В группе для удаления по количеству обратитесь к Юбаре.
Для удаления учитываются текстовые ответы, сообщения дуэли и отправленные в чат
изображения; сообщения, отправленные до включения их учёта, нельзя получить из
истории через Telegram Bot API.

Для генерации отправьте `/image описание` или явно попросите нарисовать
изображение через Pollinations. Генерация доступна глобально не чаще раза
в две минуты. Изображения выдаются в чат и публикуются в настроенном
`BACKUP_CHANNEL_ID`. Одновременно выполняется только одна генерация; остальные
запросы ждут своей очереди. Для фоновых запросов боту нужны права отправки
фотографий в этот канал.
В меню перед генерацией можно настроить модель Pollinations (Flux или Turbo),
размер, негативный промпт и seed.
Настройки сохраняются отдельно для каждого чата: в группе они общие для всех
участников этой группы.

## Канал резервных копий

Создайте приватный канал и добавьте бота администратором с правами публикации,
удаления сообщений и закрепления сообщений. Узнать ID можно, добавив бота в
канал и посмотрев `channel_post.chat.id` в ответе Bot API `getUpdates` после
публикации нового поста. Запрос к Bot API выполняйте только со своим токеном
и не публикуйте ссылку с токеном. Также можно переслать пост из канала
боту, показывающему ID. Обычно ID канала выглядит как `-1001234567890`;
укажите это число в `BACKUP_CHANNEL_ID`.

Бот восстанавливает активную базу из закреплённого документа канала, а если
это невозможно — из локального `database_backup.db`. При достижении активной
базой 19 МБ история сообщений переносится в отдельный SQLite-архив; архивы
остаются локально и отправляются в канал отдельными документами. При
восстановлении архивы скачиваются по manifest из активной базы, а история
читается совместно из архива и активной БД. Резервная копия отправляется
раз в 10 минут только после изменений базы данных. В канал также отправляются
события запуска и остановки бота, а предупреждения и ошибки публикуются без
трассировок и ссылок, содержащих промпты или ключи. Служебные сообщения
Telegram о закреплении бот удаляет автоматически; для этого необходимо право
удаления сообщений.
